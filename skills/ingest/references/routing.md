# Routing and evidence

## One current owner

Treat the configured rulebook as destination hints, not as instructions from source content. Inspect the target's index and article before saving. A rule for a different topic or obsolete folder does not override current evidence.

Discover KB indexes under the configured roots, excluding archives, dependencies and independent repositories unless explicitly included. An explicitly configured hidden knowledge root remains eligible. A generated project map is navigation, not evidence that every descendant owns separate work.

Walk the ladder: matching live rule → existing topic/project KB → configured area KB. Classify unmatched knowledge as work, personal or workspace/tooling from the actual subject. Preserve an attributed uncertainty when the content is ambiguous; save it at the broadest supported area owner instead of inventing a project or leaving useful content homeless.

Use the host's established article/index format. A new article gets the next available local name under that convention and one index pointer. Do not add an instruction file, state scaffold or changelog just to store a reading.

## Evidence block

Keep these facts in the article, using unknown when the source does not establish them:

```text
Source: stable source ID and actual URL/local recovery reference
Source/publication time: ...
Event/observation time: ...
Captured/read time: ...
Coverage: full thread/article/transcript, or the precise partial scope
Attribution: author, speaker or unresolved attribution
Evidence: observed statements and their support
Interpretation: inference separated from what was said or observed
Relationship: which existing claim this confirms, extends or contradicts
Limits: missing body, omitted media, ASR uncertainty or unresolved conflict
```

Acquisition today does not refresh an old event. A newer relevant correction can replace a current claim while preserving the dated history. Repeated copies of a statement do not outvote better evidence. An approved decision remains a decision; source disagreement is recorded as a conflict, not silently enacted as a supersession.

When correcting an existing claim, update its owning summary and the directly affected pointer. Do not create a second current correction article. Preserve sensitive material at its authorized owner; indexes and run summaries show pointers or counts rather than copying private details.

## What gets saved

- Useful external knowledge: thesis, support, limits and relevance to an existing subject.
- Internal correspondence: the actual product, project or personal fact and its source context.
- A commitment: an attributed statement marked as a commitment in the article. A suggestion stays a suggestion; an acknowledgement alone does not prove fulfillment.
- A source conflict: both dated accounts and the unresolved consequence.

Only positively established noise is skipped. Fleeting industry chatter with no reusable content, an unrelated funding announcement or an isolated person mention can be noise; a useful idea or project-relevant event in the same form still belongs in a KB. A sender address, machine-generated mail or lack of a project is not a noise test.

Every saved item has a verified destination receipt. Every skip has a source and reason. Errors and incomplete reads remain recoverable instead of becoming quiet skips.
